**English:** 1)<br/>
a) In a buddy system, up to 50% of space can be wasted due to internal fragmentation.<br/>
True, because buddy-system block sizes are powers of two; for 2 bytes of memory, if only 1 byte is used, then 50% is wasted.<br/>
b) The first-fit allocation algorithm is slower than best-fit (on average).<br/>
False; both have time complexity O(n), but first-fit is fast early and slower later, whereas best-fit must search the entire heap each time, so it is slower than first-fit.<br/>
c) Using boundary tags for freeing is fast only when the free list is sorted by increasing memory address.<br/>
False; if the free list is sorted by increasing address, a newly freed block must traverse the free list sequentially to find the appropriate predecessor, which is actually slower than LIFO, where freeing is constant time.<br/>
d) The buddy system has only internal fragmentation, never external fragmentation.<br/>
False; if memory is requested in increasing sizes and never freed, the small blocks cannot be merged into larger blocks, which produces external fragmentation.<br/>

**English:** 2)<br/>
a) On a free list sorted by decreasing block size, first-fit leads to poor allocation performance but avoids external fragmentation.<br/>
False; it cannot avoid external fragmentation — if memory is requested from small to large, the large blocks all get allocated in the end, and new requests cannot find a suitable block.<br/>
b) For best-fit, the free list should be sorted by increasing memory address.<br/>
False; the addresses increase but block sizes are random, so you still have to search the entire free list.<br/>
c) Best-fit selects the largest free block that matches the requested segment.<br/>
False; it should select the best-fitting block, not the largest.<br/>
d) On a free list sorted by increasing block size, first-fit is equivalent to best-fit.<br/>
True, but best-fit must search the entire free list, so it is less efficient.<br/>

**English:** 3) A Mark&Sweep garbage collector is called conservative under which of the following conditions?<br/>
a) It coalesces freed memory only when a memory request cannot be satisfied.<br/>
No, this is a way to improve efficiency.<br/>
b) It treats anything that looks like a pointer as a pointer.<br/>
Yes.<br/>
c) It runs garbage collection only when memory is exhausted.<br/>
No, this is a garbage-collection optimization.<br/>
d) It does not free memory blocks that form circular linked lists.<br/>
No, that would be a memory leak.<br/>
